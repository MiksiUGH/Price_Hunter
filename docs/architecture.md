# Архитектура проекта PriceHunter

## Общая структура

Проект состоит из одного Django-приложения `core`, которое содержит модели, вьюхи, шаблоны, статику, утилиты и кастомные команды.
```core/
├── models.py # Модели БД
├── views.py # Контроллеры (вьюхи)
├── admin.py # Настройки админки
├── forms.py # Формы (логин, регистрация, смена пароля)
├── urls.py # URL-маршруты
├── management/commands/ # Кастомные команды
│ ├── update_all_offers.py
│ ├── update_favorites.py
│ └── cleanup_subscriptions.py
├── utils/
│ ├── parsers.py # Парсеры маркетплейсов (AbstractParser, WbParser)
│ ├── product_utils.py # Работа с продуктами (создание, поиск, сохранение)
│ ├── string_utils.py # Нормализация строк, очистка названий, даты доставки
│ └── ...
├── templates/ # HTML-шаблоны
│ ├── core/
│ │ ├── index.html
│ │ ├── profile.html
│ │ ├── settings.html
│ │ ├── instruction.html
│ │ ├── auth.html
│ │ └── email/ # HTML-шаблоны писем
│ │ ├── significant_change.html
│ │ └── periodic_summary.html
│ └── includes/ # Переиспользуемые фрагменты
└── static/ # CSS, JS, изображения
```
## Модели данных

- **Shop** – маркетплейс (slug, название, активность).
- **Product** – абстрактный товар (название, slug, нормализованное имя).
- **Offer** – конкретное предложение (ссылка, цена, наличие, срок доставки, привязка к продукту и магазину).
- **PriceHistory** – история цен и наличия (для отслеживания изменений).
- **Subscription** – подписка пользователя на предложение (флаги уведомлений, last_notified_price, last_notified_delivery_days).
- **UserSetting** – настройки пользователя (тема, валюта, интервал проверки, email_notifications, price_change_threshold, last_checked_at).

## Бизнес-логика

### Поиск товаров

1. Пользователь вводит запрос на главной странице, выбирает фильтры и нажимает «Искать».
2. Вьюха `query_search()` нормализует запрос и ищет точные и нечёткие совпадения среди `Product.normalized_name`.
3. Если найдено достаточно продуктов (≥30), возвращает их карточки.
4. Иначе запускает парсеры (по одному на маркетплейс) с ограничением `answer_cnt = 30 - count_found`.
5. Парсер возвращает список предложений, которые сохраняются через `save_parsed_offer()` (создание/обновление `Product`, `Offer`, `PriceHistory`).
6. Результаты объединяются и возвращаются в виде HTML-фрагмента.

### Страница предложений продукта

- Вьюха `product_offers()` получает продукт по slug.
- Загружает все активные предложения (`Offer.is_active=True`) и помечает избранное текущего пользователя.
- Передаёт в шаблон фильтры и цены для диапазона.
- На клиенте JS выполняет дополнительную фильтрацию и сортировку без перезагрузки страницы.

### Избранное (подписки)

- `FavoritesView` обрабатывает POST (добавить) и DELETE (удалить).
- При добавлении создаётся `Subscription` с `is_active=True`, `last_notified_price = offer.price`, `last_notified_delivery_days = offer.delivery_days`.
- При удалении – деактивация (`is_active=False`).

### Обновление данных и уведомления

Две независимые команды:

1. **`update_all_offers`** – запускается по cron (раз в час):
   - Собирает все активные предложения (`Offer.is_active=True`).
   - Группирует по магазинам.
   - Для каждого магазина вызывает `parser.update_and_save_batch(urls)`.
   - Обновляет цены, наличие, доставку, создаёт `PriceHistory`.

2. **`update_favorites`** – запускается после обновления (или отдельно):
   - Загружает все активные подписки с пользователями и офферами.
   - Кэширует две последние записи истории цен для каждого оффера.
   - Для каждого пользователя проверяет настройки (`email_notifications`, `price_change_threshold`, `check_interval`, `last_checked_at`).
   - Для каждой подписки:
     * Если `last_notified_price` или `last_notified_delivery_days` None – инициализирует текущими значениями.
     * Определяет значимые изменения: цена (процент >= порога), наличие (изменение по сравнению с предыдущей записью), доставка (отличается от last_notified).
     * Если изменения есть – формирует письмо `significant_change.html` с деталями.
     * Если изменений нет, но с момента `last_checked_at` прошло `check_interval` часов – отправляет плановую сводку `periodic_summary.html`.
     * После отправки обновляет `last_notified_price`, `last_notified_delivery_days` и `last_checked_at`.

### Email-уведомления

- Используется `EmailMultiAlternatives` с текстовой и HTML-версией.
- Шаблоны писем лежат в `templates/email/`.
- Стили встроены в `<style>` для совместимости с почтовыми клиентами.
- В письмах отображается валюта пользователя и строка доставки (например, «5 дн.» или «не указан»).

## Парсеры

- Абстрактный класс `AbstractParser` определяет интерфейс.
- Реализован только `WbParser` (Wildberries).
- Используется Selenium с ChromeDriver, headless-режим, маскировка автоматизации (user-agent, отключение WebDriver).
- Методы:
  - `search_by_query()` – поиск по названию с пагинацией, фильтрацией по цене и доставке.
  - `search_by_url()` – получение данных одного товара.
  - `update_by_url()` – обновление цены, наличия, названия, доставки (используется внутри `update_and_save_batch`).
  - `update_and_save_batch()` – массовое обновление: один драйвер на все URL, транзакции, очистка названий, обработка ошибок.

## Фронтенд

- **Главная страница (`index.html`)** – переключение между поиском по названию и по URL, фильтры (цена, доставка, маркетплейсы). JS (`main.js`) отвечает за сбор параметров и отправку запроса только по кнопке или Enter.
- **Страница предложений (`product_offers.html`)** – клиентская фильтрация и сортировка (цена, магазин, доставка). JS (`product_offers.js`) обрабатывает изменения и перерисовывает карточки.
- **Профиль (`profile.html`)** – отображение избранных товаров, клиентские фильтры, удаление из избранного, кнопка удаления аккаунта.
- **Настройки (`settings.html`)** – форма для изменения темы, валюты, интервала, порога, включения email.
- **Инструкция (`instruction.html`)** – статическая страница с описанием всех функций.
- **Общие скрипты (`common.js`)** – бургер-меню, загрузка темы, обработка кнопок избранного (AJAX POST/DELETE), модальное окно для неавторизованных.

## Запуск в production

- Установить переменные окружения (секреты).
- Собрать статику.
- Перейти на PostgreSQL (рекомендуется).
- Настроить веб-сервер (nginx + gunicorn).
- Настроить cron для команд.

## Безопасность

- CSRF-защита включена.
- Пароли хешируются Django.
- Email-пароль хранится в переменных окружения.
- При деплое `DEBUG=False`, `ALLOWED_HOSTS` ограничен.
- В парсере используются маскировки (fake-user-agent, отключение webdriver).
